# مراجعة اختبار الجدوى: إدارة العملاء بدون adula-kit

**المطلوب (جملة واحدة):** «أريد إدارة العملاء: الاسم إلزامي وفريد، والبريد والهاتف والعنوان اختيارية، مع قائمة قابلة للبحث والترتيب، ونموذج إنشاء وتعديل، وصفحة تفاصيل، وحذف منطقي، وصلاحيات بحيث يرى الموظف عملاء وحدته فقط ويعدّل المدير.»

**التنفيذ:** AdonisJS 7 + Inertia React من القالب الرسمي `starter-kits-main/inertia-react`، دون `@adula/kit` ودون `@adula/ui`، على PostgreSQL 17.

## 1. التشغيل (5 دقائق)

```bash
cd tests/feasibility-exercise/app
cp .env.example .env   # ثم ضع APP_KEY (node ace generate:key) وكلمة مرور قاعدة البيانات
pnpm install --ignore-workspace
source /root/adula-env.sh
# ملاحظة: adula-env يضبط DB_DATABASE=adula_test و NODE_ENV=test، لذا نتجاوزهما صراحةً:
export NODE_ENV=development DB_DATABASE=feasibility_dev SESSION_DRIVER=cookie PORT=3395 APP_URL=http://127.0.0.1:3395
node ace migration:run
node ace db:seed
node ace serve --hmr        # ثم افتح http://127.0.0.1:3395/login

# التحقق
pnpm lint
pnpm typecheck
pnpm test                   # يستخدم feasibility_test فقط (مثبت في سكربت test)
```

## 4. متطلبات فسّرتها بنفسي (قرّر إن كانت صحيحة)

1. **نطاق المدير:** المدير يرى ويعدّل **عملاء وحدته فقط** (أقل صلاحية). إن كان المقصود أن المدير يرى كل الوحدات فالتعديل سطر واحد في `customer_policy.ts` وفي استعلام القائمة.
2. **الموظف للقراءة فقط:** لا ينشئ ولا يعدّل ولا يحذف. فسّرت «ويعدّل المدير» بأن الكتابة كلها للمدير.
3. **التفرد عالمي** على مستوى الشركة (لا لكل وحدة)، دون اعتبار حالة الأحرف، ولا يشمل المحذوفين منطقياً، فيمكن إعادة استخدام اسم عميل محذوف.
4. **الوحدة** تُؤخذ من المستخدم المنشئ، ولا يختارها المستخدم في النموذج.
5. **الحذف:** للمدير فقط، ويسجّل `deleted_at` و`deleted_by`؛ لا توجد واجهة استرجاع.
6. **صيغة الهاتف:** أرقام ومسافات وشرطات و`+` اختيارية (6–20 حرفاً)؛ لا تحقق دولي.
7. **البحث** في الاسم والبريد والهاتف (ليس العنوان)، والترتيب بالاسم أو البريد أو الهاتف أو تاريخ الإضافة.

## 5. اختصارات وحدود معروفة

- **لا shadcn/ui:** لم أثبّته (لا يأتي مع القالب ولم أتحقق من توفره دون اتصال)؛ استخدمت عناصر HTML أصلية مع وسوم إتاحة (`label`، `aria-invalid`، `aria-describedby`، `aria-sort`) وCSS بسيط. هذا **مخالف** لقاعدة المستودع للواجهات.
- **النماذج والتفاصيل صفحات مستقلة** وليست Dialog، خلافاً لقاعدة المستودع الافتراضية.
- **لا هوية بصرية:** لم يُطلب اسم الشركة أو شعارها أو ألوانها، ولا يوجد `docs/design-identity.md`.
- **أُزيل التسجيل الذاتي** (`signup`) لأن المستخدم الجديد بلا وحدة ولا دور؛ الحسابات من الـ seeder فقط. لا توجد إدارة للمستخدمين أو الوحدات.
- **لا Bouncer:** الصلاحيات في كائن سياسة بسيط يستدعيه المتحكم يدوياً؛ نسيان استدعائه في إجراء جديد لن يكتشفه شيء تلقائياً.
- **لا سجل تدقيق** غير `created_by` و`updated_by` و`deleted_by`، ولا تحكم في التزامن (آخر حفظ يفوز).
- **رسالة 403/404** نص خام وليست صفحة Inertia مصممة.
- بعض النصوص المولّدة من الإطار بقيت إنجليزية (مثل `E_VALIDATION_ERROR: The form could not be saved...` في `errorsBag`، ولا تظهر في الواجهة الحالية)، واسم الحقل `sort` يظهر كما هو في رسالة خطأ الترتيب.
- **اختبارات الواجهة:** لا توجد اختبارات متصفح (Playwright)؛ الاختبارات وظيفية عبر HTTP/Inertia فقط. تحققت من العرض بـ curl وليس بصرياً.
- **متغيرات البيئة:** سكربت `pnpm test` يثبّت `DB_DATABASE=feasibility_test` لأن `adula-env.sh` يصدّر `adula_test`، ومتغيرات العملية تتقدم على `.env.test` في Adonis.
- **تعديلات على القالب:** حذف `better-sqlite3`، وإضافة `pg` و`@japa/api-client` و`@inertiajs/core` (الأخير لازم ليمر `typecheck` مع pnpm)، ونقل `pnpm.overrides` إلى `pnpm-workspace.yaml`، وتعريب صفحتي الدخول والأخطاء.

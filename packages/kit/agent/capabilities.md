# adula-kit capabilities (1.0.0)

Generated by `node ace adula:capabilities`. Read this before proposing a module; anything not listed here is not provided by the kit.

## Resource definition

| Field type | Storage |
|---|---|
| string | varchar |
| text | text |
| integer | integer |
| money | bigint minor units, decimal string in JSON |
| boolean | boolean |
| date | date (YYYY-MM-DD) |
| datetime | timestamptz |
| json | jsonb |
| attachment | attachments row id; per-field accept/maxSize |
| belongsTo | foreign key, preloaded, restrict on delete |
| user | users foreign key; active members of the record organization; related as { id, fullName } |
| hasMany | child resource; inline rows saved with the parent |
| lookup | lookups group key |

Field options: required, unique (partial, active rows), sortable, searchable (generated tsvector), filterable, permissionLevel, sequence, column.

Resource options: scoped (required), submittable (docStatus, submit/cancel/amend-by-copy), version (optimistic locking, default with submittable), customFields, label (plural) / recordLabel (singular) / createLabel, title (fields naming a record in tasks and approvals), list / form / show / serialize / hidden, actions, hooks.beforeSave / hooks.afterSave.

Role rule conditions: $eq, $ne, $in, $lt, $gt, $like on scalar fields; "$actor.id" (the signed-in user) on createdBy, updatedBy and user fields; unsupported conditions are refused. Organization scope is always added with AND.

Module options: dependsOn, resources, workflows, lookups (rows by group) and defaultRoles (key, name, rules), applied by adula:install without overwriting existing rows or roles. Workflows address roles by their stable key ({ role: key }).

Workflow steps: condition, update, notify, approval, delay, http, end. Workflow and step names: use lower-case letters, digits and underscores, starting with a letter (for example release_approval, notify_approved).

## Extension points

- Resource hooks (beforeSave, afterSave) inside the save transaction
- Page override: inertia/pages/<resource>/{index,form,show}.tsx replaces the generated page
- Domain events <module>.<resource>.{created,updated,deleted,submitted,cancelled,amended} with idempotent listeners
- Module workflows (Module.workflows) with versioned definitions
- Message templates edited per deployment
- Outgoing webhooks and the bearer-token /api/v1 API (records and authorized aggregates)
- Notifications that open their record (notify target)
- Signed inbound webhooks raising inbound.<source>.<event> through the outbox

## Outside the kit

- Dynamic fields or a field editor screen
- Runtime plugins
- A visual workflow editor
- Multi-tenant SaaS in one database (one deployment per organization)
- XLSX import until a maintained parser passes the dependency rule (GAP-006)
